# Lekki critics (hero moments only)

The builder must not grade its own work. After a build, judgment uses **fresh
context**: screens and rules, not the chat that wrote the code.

**When:** Guest arrival, Go live QR, Pay at table, or another named hero
moment. Not every Studio field. The human is the brake — pause when they stop.

**When not:** Frozen structure (Setup Engine v1, Experience/Studio shells, core
guest journey). Craft inside tokens is fine; a new shell is not.

## Bar

Name one real thing a critic can open (our Live Experience, a hospitality
product screen — never “Apple’s website”). Write 5–7 **checkable** lines to
`.design/<slug>/bar.md`.

Useless: feels premium · clean · good hierarchy.  
Useful: one gold fill per screen · Fraunces only on the purpose line · motion
160/220/280/360ms · Guest is the running shell not a mock.

Show `bar.md` to the human before looping.

## Three verdicts (binary: pass or fail)

| Critic | Judges | Blind to |
|--------|--------|----------|
| **Moment** | HCI CX/DX/OX/PX + one question + one gold action | How it was coded |
| **System** | `docs/ux/lves.md`, `_tokens.scss`, motion freeze | Taste adjectives |
| **Craft** | `bar.md` + **rendered** screenshots only | Source files |

All three must pass. Any fail: name the **single biggest gap**, rebuild that
piece, judge again. No scores (they drift up). No fixed round count.

## Preflight

If you cannot screenshot the running app, the Craft critic is blind — say so
and stop. Do not invent a comparison.

Adapted from Matt Shumer’s Gauntlet / Design Loop: fresh context, not
self-review. Not a multi-agent farm and not a second design OS.
