# Studio Setup Emotion Research

**Question:** How do the world’s best products make a business owner *feel* while creating, configuring, publishing, and operating their business?  
**Not:** Which screens look nicest on Mobbin.  
**For:** LEOS Studio (calm guide) · Guest product = Lekki · LEK-040 Human Confidence  
**Frozen outcome:** [Live Experience](live-experience.md) — Studio’s defining surface (not “preview”).

**Reference set (behaviour):** Shopify · Stripe · Square · Toast · Lightspeed · Figma · Notion · Linear · Airbnb Host · SevenRooms · Resy OS · Clover · Apple Business · plus live-preview peers (Webflow · Framer · Squarespace · Canva · Stripe Payment Links · Square Online).

---

## Cross-product patterns (emotional)

| Feeling | What the best do | What weak admin does |
|---------|------------------|----------------------|
| **Anxiety ↓** | One question per step · defaults chosen · “you can change this later” | Dump every setting · Pack/capability jargon · Save? dialogs |
| **Confidence ↑** | Show the customer outcome while configuring | Ask owner to imagine the guest journey |
| **Effortless progress** | 3–7 milestones · endowed progress (start >0%) · auto-save | Infinite checklist · 0% bar · manual Save |
| **Celebration** | Discrete Go Live / Publish moment · then retire the setup guide | Silent publish · setup bar stuck at 100% forever |
| **Reassurance before irreversible** | Preview as guest · test sale · password/draft until ready | Publish with no preview |

**HCI triad (every screen):** Where am I? · What do I do? · What happens next?

---

## Navigation (business apps)

| Product archetype | Primary nav | New-business behaviour |
|-------------------|-------------|------------------------|
| **Shopify / Square** | Dense admin once live | Setup **guide** overlays home; not full nav as day-1 job |
| **Linear / Notion** | Few modes · dense tools after | Onboarding is short; product *is* the workspace |
| **Toast / SevenRooms** | Heavy ops IA | Often **assisted** onboarding + checklist; hospitality complexity deferred |
| **Airbnb Host** | Guided listing wizard | Nav almost hidden until listing exists |

**LEOS takeaway:** Setup Engine should feel like Airbnb Host / Shopify setup guide — **modes (Setup · Operate · Grow) exist**, but during Create→Go Live the owner sees **one linear confidence path**, not a marketplace of admin modules. Hide Operate density until live.

## Onboarding

| Pattern | Who | Lesson for Studio |
|---------|-----|-------------------|
| ≤5 essential steps (Shopify) | Merchants drop after ~5 | Engine already has Identity→…→Go Live — **protect count**; don’t add “advanced” mid-path |
| Checklist + progress (Shopify, Toast) | Progress without homework feel | Step indicator + “Looks good” — not task inventory |
| Defaults + deferral (Square, Linear) | Bank/taxes later; sell first | Payments can be soft; Experience + Places must feel complete |
| Assisted + self-serve (Toast, SevenRooms) | Complex hospitality | Pack complexity stays **defaults + projection**, not consultant-required UI |
| Preview before publish (Airbnb) | Host sees guest listing | **Guest projection before Go Live** is non-negotiable |

## Live preview research (killer feature)

### Models compared

| Model | Examples | Fidelity | Update speed | Fit for Studio |
|-------|----------|----------|--------------|----------------|
| **Split-screen live** | Shopify Theme Editor · Squarespace · Framer | High — same storefront | Instant / near-instant | **Best fit** for Experience + Places |
| **Canvas = product** | Webflow · Figma · Canva | Highest | Instant | Too builder-like (reject for LEOS) |
| **Side panel + preview** | Notion share preview · many CMSs | Medium | Refresh / navigate | OK for secondary |
| **Artifact preview** | Stripe Payment Links · Apple Wallet | Exact artifact | On change | Good for **QR / Go Live** |
| **Draft then publish** | Toast menu Save → Publish | POS/channels lag | Manual publish | Avoid as primary confidence model |
| **Guest-as-preview** | Airbnb “view as guest” | Exact listing | After edits | Ideal for **fullscreen Preview Experience** |

### Recommendation for LEOS Studio

**Primary interaction model: Shopify Theme Editor × Airbnb Host**

1. **Split-screen** during Experience & Places — settings left · **Live Guest Experience** right (Experience Shell projection, not a mock phone chrome-only toy).  
2. **Instant update** — toggle Drinks → Drinks vanish; select Table 12 → arrival shows Table 12. No refresh.  
3. **Fidelity rule:** Preview uses the **same Experience Shell components / grammar** guests get; Pack supplies content; Studio never invents a second UI.  
4. **Fullscreen “Preview Experience”** — Airbnb “view as guest”: no Studio chrome.  
5. **Go Live** — Stripe/Airbnb artifact moment: QR is the published pass; preview *becomes* reality (same projection, live session).  
6. **Reject:** Webflow/Figma freeform canvas · Toast “save then hope publish worked” as the only feedback.

**Why this is the differentiator:** Most POS/admin asks owners to *configure and hope*. LEOS lets them **experience their experience** before guests do — LEK-040 *Never Ask a Human to Remember* applied to outcomes, not just data entry.

## Recommendations specifically for LEOS Studio

### Emotional journey (freeze)

```text
Welcome → Choose Experience → Identity → Experience → Places → Payments → Go Live → Operate → Grow
```

Each step = **one human question** (already aligned):

| Step | Confidence question |
|------|---------------------|
| Welcome | Can I start without fear? |
| Choose Experience | Do I know what I’m creating? |
| Identity | Is this place named? |
| Experience | Do I know exactly what guests will experience? |
| Places | Where will guests join? Does each place have identity? |
| Payments | How do they pay? (deferral OK if soft) |
| Go Live | Am I live? Can I open the guest path? |
| Operate | Can I run under pressure? |
| Grow | Do I see calm truth? |

### Product rules

1. **Studio ≠ admin panel.** Calm guide · brand Lekki · tool Studio (after Get Started).  
2. **Live Experience Preview is a platform promise**, not a nice-to-have — invest here over Marketplace/Neo.  
3. **Auto-save + Saved ✓** everywhere in Setup. Never Save?.  
4. **Looks good — Continue to…** language on Experience & Places (done).  
5. **Defaults from Experience type** (Pack internal) — owner designs *presence*, not schema.  
6. **Celebrate once** at Go Live; retire Setup density; open Operate on **status**.  
7. **Nav:** Setup · Operate · Grow only; during Engine, progress strip > mode noise.  
8. **No builder:** projection of Experience Shell only (constitution + IA freeze).

### Preview fidelity roadmap

| Now | Next | Later |
|-----|------|--------|
| Experience Shell projection + Places arrival preview | Shared projection package used by guest + Studio | Optional iframe of `/e/:token` seed when runtime session available |
| Fullscreen Preview Experience | Same shell, gated demo session | QR opens identical shell |

### What *not* to copy from Mobbin screenshots

- Dense Shopify left-nav as day-1 Setup  
- Toast multi-week checklist anxiety  
- SevenRooms consultant-gated “required settings” walls  
- Linear dark density for hospitality owners  
- Webflow canvas as “experience builder”

## Success test

An owner can say before Go Live:

> “Yes — that’s exactly what my guest will see.”

If yes → HCI green on Experience + Places.  
If they must *imagine* → preview fidelity is still insufficient.
