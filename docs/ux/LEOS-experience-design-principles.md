# LEOS Experience Design Principles

**Status:** UX constitution (1 page)  
**Not this document:** LEDS, colours, typography, components  
**Applies to:** All Experience Packs — Restaurant is only the first proof

---

## Context first

The user should always know where they are.

- Venue  
- Physical Context  
- Session  

If they cannot answer “where am I?” in one glance, the screen fails.

## Uncertainty removed

Every screen removes one uncertainty (Entry: right place? · Cart: what am I committing to? · Live: is it progressing?).  
If it removes nothing, it should not exist ([BUILDING-LEOS](../BUILDING-LEOS.md)).

---

## One primary action

Every screen has one obvious next step.

Secondary actions exist. They never compete with the primary.

---

## Progressive disclosure

Show only what is needed now.

Advanced options stay hidden until required.

---

## Live by default

Sessions update automatically.

Users never refresh to discover truth.

---

## Never lose context

If the connection drops, users return to where they were.

Offline must preserve Intent. Reconnect must restore Session.

---

## Mobile first

Every experience begins on a phone.

Desktop expands the same grammar — it does not redesign it.

---

## Runtime over Pack

Core screens should feel familiar whether the user is in a restaurant, hotel, or festival.

Packs supply terminology and content. Runtimes and layout grammar stay stable.

## Experience Review (freeze gate)

Before freeze: Understandable · Obvious · Calm · Trustworthy · **Reusable**.  
If not reusable across packs, it is not a LEOS screen ([BUILDING-LEOS](../BUILDING-LEOS.md)).
